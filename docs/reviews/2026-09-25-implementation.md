# 应用层优化实施与验证记录

日期：2026-09-25。分支：`feat/dictation-reliability`。Issue：[Echos #2](https://github.com/michaelmjhhhh/Echos/issues/2)。

本次以英语口述为主要使用场景，保持默认 Distil Large v3 模型和现有模型权重不变。依据 [代码审查](2026-09-25-codebase-review.md)，修复应用层的确定性缺陷，并加入可复现的本地回放工具。没有把合成样本结果当作真实口述准确率提升。

## 已实施

| 范围 | 问题与处理 |
| --- | --- |
| 短录音及尾部 | WhisperKit 的一秒窗口边界可跳过短录音，亦可漏掉 30 秒边界后的不足一秒尾部。给解码输入追加一秒合成静音，使实际录音全部进入处理范围；录音时长、统计和历史不包含这段填充。预热要求实际编码器运行成功。 |
| 录音生命周期 | 使用录音代次及会话标识，区分传输就绪与出现声音。以最终采集结果判断可用性；转换器在新录音前重置，松键后短暂等待硬件尾帧并按时间戳裁剪。设备变化、中断、输入缺口和回退设备有明确反馈。 |
| 取消与恢复 | 取消、推理超时、休眠、权限变化均受会话身份约束。晚到结果不会粘贴、入历史或改变新会话。旧推理真正退出前保留引擎占用。模型失败不会假装就绪；支持同模型重试和修复。 |
| 粘贴与剪贴板 | 保存原始应用、窗口和可获取的焦点元素。结果返回及提交前重新校验，目标变化时保留手动复制入口。只有剪贴板仍由本次操作占用时才恢复；支持原剪贴板为空、连续操作和安全输入变化。复制写入失败不会显示已复制。 |
| 文本处理 | 每一阶段从原输入选择互不重叠的匹配，不递归扫描替换结果。最长匹配优先；支持标点术语、Unicode、中文边界及英文所有格。保护 URL、邮件地址和代码；可显式允许受保护文本替换。保留 snippet 的字面换行和首尾空白。 |
| 个性化 | 检测别名冲突，支持批量词典导入、snippet 独立短语模式和关闭扩展。每次口述固定规则与配置快照。语言选项按模型能力生效，英语模型不会因为保存过中文偏好而无法使用。 |
| 推理策略 | 提供提示词预算与困难音频重试设置，默认值维持原策略。缓存提示 token；记录真实使用 token 数。只直接拒绝精确数字静音，保留低音量和不确定音频；用可用诊断信号提示复核，不把未校准分数当作置信概率。 |
| 模型安装 | 启动与模型目录共享下载所有权，修复排队，取消订阅后不允许重复写入。检查模型结构和 tokenizer，实际加载与预热后才进入就绪。离线加载显式使用本地 tokenizer，不隐式联网。 |
| 持久化 | 词典、snippet 和历史保存失败可见并可重试；损坏原文件不静默覆盖，支持恢复。历史异步顺序保存，正常退出先等待当前操作结束，再刷新历史和统计。显式历史删除清理其备份及恢复副本，避免删除后复活。 |
| 统计与隐私 | 区分识别、粘贴事件发出、复制、待复制、取消及失败；不声称已验证目标收到文本。识别词数与扩展词数分开，视图读取后台 SQLite 汇总缓存。统计独立开关、保留期限、删除和汇总导出；不记录音频、转写正文、词典提示或剪贴板内容。 |
| 界面 | 提供取消、重试、修复、完整历史、单条删除、纠错及保存状态；复制结果不再十秒后不可恢复。修复首次悬浮条不可见问题，取消中和自动复制有对应提示。 |
| 构建及评估 | 固定 Argmax/WhisperKit 0.18.0 和全部依赖 revision；生成项目时恢复受版本管理的 lock。新增 `EchoEvaluate`、本地样本生成脚本和 CI；发布依赖完整验证门禁。 |

### 固定权重的实际推理

默认 Distil 模型的组合文件 SHA-256 在前后回放中一致：

`da94f53244964346a18e2fd273c2556100997b4a4a1b97053cb552e07b27d481`

使用本机合成的英文 “Yes” 和数字静音，未读取个人录音：

- 0.3、0.5、0.8、1.0、1.2 秒短句均进入编码器并返回 `Yes.`；2% 幅度的低音量样本保留。Tiny English 也通过相同的八种样本验证，应用默认模型没有切换。
- 最终矩阵为 8 种样本 × 2 次 × 5 种提示预算 × 裁剪开/关，共 160 次。120 次语音结果无词错误或误拒绝，40 次数字静音没有误插入。
- 31 秒和 61 秒样本修复前分别只运行 1、2 个编码窗口，修复后运行 2、3 个，取回原先完全未解码的尾部词。29、30、59、60 秒样本的编码窗口数量和文本没有因此改变。
- 160 次矩阵中的语音推理中位数约 0.686 秒、p95 约 0.711 秒，仅描述本机短合成样本。编码器约占 0.600 秒，解码器约占 0.080 秒；不是端到端真实口述延迟，也不是相对旧版的速度提升比例。
- 该词典只有 `Echo`、`OpenAI`：非零预算实际用了 4 个 token，不能据此推断 200 token 或 1,000 项词典的性能。120 次语音调用出现 71 次提示缓存命中。
- 首次 CoreML 专用化的加载加预热约 12.28 秒，缓存后的加载加预热约 1.39 秒。不能混合这两种状态进行速度比较。

可复现入口及评分规则见 [回放文档](../evaluation.md)。紧凑结果见 [实际回放记录](2026-09-25-replay-results.json)。

## 尚未由本次验证证明的内容

真实口述的总体 WER/CER、专有名词召回、口音、噪声环境及长段自然语音质量，仍需明确采集的本地英语评估集。合成重复单词在单一长窗口内仍可能被模型合并，本次没有声称解决模型本身的这一行为。

蓝牙首帧与尾帧、不同采样率的真实硬件、休眠和拔插、权限撤销、左右修饰键组合，以及原生/Electron/浏览器/安全输入的实际粘贴矩阵，仍需设备和应用验收。已做转换器与状态集成检查不等于这些真实场景全部通过。跨进程焦点与粘贴事件也不存在系统级原子提交保证。

没有启用尚无真实语料支撑的激进噪声过滤、降低默认重试或增量推理。原审查把增量推理列为条件性实验；当前合成回放显示编码器成本更高，不足以证明新增增量路径的质量、功耗和复杂度合理。现有参数与回放工具提供后续成对比较的入口。

## 麦克风回归修复与发布

用户实际反馈：选 System Default 或 MacBook Air 麦克风，按 Fn 后波形立即消失；选进程私有聚合设备则可用。

使用签名的临时原生诊断应用运行生产录音代码，在原有麦克风授权下复现：启动后约 0.17 秒收到配置通知，此时引擎仍运行且格式为 48 kHz 单声道。原实现无条件报告中断，控制器把不足 0.3 秒的会话静默结束。诊断仅在内存接收音频，未保存或转写。

修复默认路由重复绑定，只有当前引擎停止、格式改变或默认输入改变才把配置通知视为中断；真实短中断显示错误。私有聚合设备按 Core Audio 的 private 属性排除，旧临时 UID 迁移至 System Default；公开聚合设备和 Teams 虚拟输入保留。蓝牙唤醒仅用于实际蓝牙输入，异步菜单枚举不会用过期结果覆盖新列表。

- 修复前两个输入均产生 `interrupted=true`；修复后两次冷启动均收到有效音频、零丢帧、无中断。
- 同一录音器连续执行默认冷启动、默认热启动、显式内置、返回默认共四轮，各约 1.5 秒：每轮收到约 24,000–25,600 个 16 kHz 样本、17 个转换缓冲、零丢帧、无中断。录音运行中目录只显示内置与 Teams，没有私有聚合设备。
- 设备迁移探针确认两种 reserved PID UID 会清除，离线物理设备 UID 和类似但非 reserved UID 保留。
- 修复后重新运行 `scripts/ci.sh`：173 项全部通过，评估器 Release 构建、六种音频文件检查和依赖锁检查通过；没有再修改测试。
- v0.4.0 (4) 应用 Release 构建及本机开发签名校验通过。正常退出旧版后启动新构建，实际保存的旧私有设备选择自动迁回 System Default；设置菜单只显示默认、MacBook Air 和 Teams，应用进入 Ready，默认模型和 Fn 快捷键保留，没有修改系统权限。
- 独立复核确认旧引擎通知隔离、真实路由变化处理及 CFDictionary 所有权无阻断问题。蓝牙、USB、自建聚合设备和拔插仍需对应硬件验收。

用户随后授权维护 changelog、拆分提交、创建 PR、合并 main 并发布 v0.4.0。构建、远端验证与发布结果以 PR 和 Release 记录为准。仓库原有 `.pi-subagents/artifacts` 删除不纳入提交；未修改系统权限。
